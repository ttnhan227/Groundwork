# Groundwork desktop foundation audit — 5 October 2026

The previous architecture coupled file discovery with text parsing: unsupported formats, empty files, credentials, Git-ignored files, dependency folders, and build folders were absent from the file database. The interface presented indexed-content counts as file counts. AI used broad search results in addition to selected files. The desktop shell already isolated a loopback API with a per-launch token, validated workspace paths, offered local account-free use, and kept cloud sync opt-in.

## Implemented direction

- `InventoryService` stores metadata separately from `files`, FTS, chunks, and embeddings. It scans selected roots without reading contents, commits batches of 256 entries, lists hidden and unsupported files, records access errors, and does not traverse symlinks or junctions. Link entries appear separately and do not inflate file counts or sizes. Sizes are logical file bytes, not allocated disk space; hard links are counted by pathname.
- Metadata scanning across all selected roots precedes content preparation. Readers use SQLite WAL while the worker continues. Cancellation preserves partial inventories and never claims 100% completion. Access-limited scans preserve older entries and explain that totals may be incomplete or stale. Folder totals sort correctly after a complete scan; partial scan totals remain provisional.
- The Files view provides name/path search, extension filtering, sorting, paging, folder navigation, file selection, opening, and revealing. Global search defaults to inventory names and paths. Content search remains a separate option for readable formats. Global inventory counts and name-search results deduplicate overlapping roots; each root retains its own inventory.
- The watcher updates metadata for unsupported files before content filters. Full rescans reconcile changes missed while closed. Opening does not prove reading; modification/activity history makes no such claim. Indexing runs have their own activity type.
- AI receives only explicitly selected file excerpts, at most six files and 40 lines per file. No automatic corpus search, project metadata, saved session contents, or Git history enters the prompt. No selection/no readable text returns locally without calling a provider. Credentials and unsupported formats are excluded from reading. Provider disclosure explains cloud transmission. Local matching passages and Ollama remain optional.
- Your computer shows battery, CPU, memory, and storage. It opens trusted Windows utilities, the installed-app chooser, and HTTP(S) websites without shell interpretation. Existing open/reveal actions retain selected-root validation; executable/script formats require using the file manager. Screenshot capture requires an expiring, action-bound, single-use confirmation and saves locally without automatic upload. No destructive actions were added.
- Native debug mode runs Python source, Vite ignores the Rust build tree, and Tauri watches backend application source. Development data stays in `%LOCALAPPDATA%\GroundworkDevelopment`. Existing local welcome/sign-in choices and ordinary settings without service URLs are retained.

## Verification and remaining product boundaries

Regression tests cover unsupported/hidden/empty inventories, folder totals, live metadata updates, cancellation, access errors, junction loops, selected-file AI, dangerous URL schemes, and screenshot confirmation replay. Native UI checks cover live computer readings, screenshot review, and an existing selected folder's inventory. The full backend suite, frontend build/type checks, and native development build are run before handoff.

Clipboard, voice, browser integration, and remote access remain later work as requested. Scanned/image-only PDFs, office documents, photos, audio, and video have metadata but no content understanding. Large-drive performance and accessibility should receive further real-user validation before usability approval. Screenshot confirmation/cancellation is exercised in the native UI; capture implementation is verified with a synthetic image in tests so verification does not capture unrelated private screens. No releases, tags, installers, or Tenvora changes are part of this work.
